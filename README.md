# spechurl

[![CI](https://github.com/hamarshehmhmd/spechurl/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/hamarshehmhmd/spechurl/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/github/license/hamarshehmhmd/spechurl)](https://github.com/hamarshehmhmd/spechurl/blob/main/LICENSE)
[![GitHub release](https://img.shields.io/github/v/release/hamarshehmhmd/spechurl)](https://github.com/hamarshehmhmd/spechurl/releases/latest)

OpenAPI 3 documents become Hurl contract tests, and a CI drift check keeps the committed suite in step with the spec.

spechurl turns an OpenAPI 3.x document into a directory of [Hurl](https://hurl.dev) files: one HTTP contract test per operation, stored as plain text in git.

Backend teams use it when contract tests should review like code. There is no collection database and no GUI. The spec stays the source of truth, and `spechurl check` fails CI when the committed Hurl suite drifts from it.

## Install

spechurl is a single Rust binary. From a clone of this repository:

```bash
cargo install --path . --locked
spechurl --version
```

Or build it in place:

```bash
cargo build --release
./target/release/spechurl --help
```

You need Rust 1.85 or newer (`rustup` will pick up `rust-toolchain.toml`). [Hurl](https://hurl.dev/docs/installation.html) is separate: install it when you want to *run* the generated files. spechurl only writes and compares them.

## Quickstart

Generate a suite from the included pet store, then confirm the directory matches the spec:

```bash
spechurl generate fixtures/petstore.yaml --out hurl
spechurl check fixtures/petstore.yaml --dir hurl
```

`generate` writes one `.hurl` file per operation plus `hurl/README.md`. `check` regenerates the suite in memory and exits non-zero if that directory differs. Run the tests with Hurl when you have an API to point at:

```bash
hurl --variable base_url=https://petstore.example.com --test hurl
```

`base_url` is the server origin and any base path, with no trailing slash. Paths come from the spec.

`fixtures/petstore.yaml` produces this `post_pets.hurl` verbatim:

```hurl
# Generated by spechurl 0.1.0. Do not edit by hand.
# Source: petstore.yaml
# operationId: createPet
# POST /pets
# Create a pet
# tags: pets
# Run: hurl --variable base_url=https://petstore.example.com --test post_pets.hurl

POST {{base_url}}/pets
Accept: application/json
Content-Type: application/json
{
  "name": "Fluffy",
  "photoUrls": [
    "https://example.com/fluffy.jpg"
  ],
  "tag": "dog"
}

HTTP 201
[Asserts]
header "Content-Type" contains "application/json"
```

Do not edit the Hurl by hand. Change the OpenAPI document and regenerate. `check` is there so a drive-by edit or a stale file fails the build.

## Commands

```text
spechurl generate <openapi.yaml|json> [--out DIR]
spechurl check <openapi.yaml|json> [--dir DIR]
spechurl --version
spechurl --help
```

| Command | What it does |
| --- | --- |
| `generate` | Parse the spec and write the suite. Default directory is `hurl/`. Existing generated files are overwritten. Other files in the directory are left alone. |
| `check` | Compare `DIR` (default `hurl/`) with what `generate` would write. Missing, changed, and extra `.hurl` files are drift. `README.md` is part of the suite. |

Exit codes:

| Code | Meaning |
| --- | --- |
| 0 | Success |
| 1 | The committed suite does not match the spec |
| 2 | The spec is missing, unreadable, or not usable OpenAPI |

`check` treats CRLF and LF as the same file, so a Windows checkout does not look like drift.

## What gets generated

spechurl reads OpenAPI 3.0 and 3.1 (YAML or JSON):

- Every path and method (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`, `TRACE`), in path order.
- Path, query, and header parameters, including `$ref`s into `#/components`.
- Request bodies. JSON is preferred, then form (`application/x-www-form-urlencoded`), then text and XML.
- One success status assertion per operation.

File names are `{method}_{path}.hurl` with a stable slug: `GET /pets/{petId}` becomes `get_pets_petid.hurl`. A collision gets a numeric suffix (`get_a_b_2.hurl`).

Samples are chosen in this order:

1. `const`, `example`, `default`, or the first schema `examples` entry.
2. The first `enum` value.
3. A media-type example (names are sorted, so the result does not depend on YAML key order).
4. A minimal value from the schema. Objects include `required` properties, or every property when none are required. `readOnly` properties are left out of request bodies. Cycles become `null`.

Optional query and header parameters are emitted only when the spec gives an example, default, or `const`. Required ones are always emitted. Path parameters are filled from that same sample and percent-encoded into the URL.

Status selection is fixed: `200` if it is documented, otherwise `201`, otherwise the lowest other 2xx code. A spec that only says `2XX` becomes:

```hurl
HTTP *
[Asserts]
status >= 200
status < 300
```

Other documented success codes are listed in a comment. If the spec has no 2xx response, spechurl asserts the lowest documented status and says so.

Object keys in JSON bodies are sorted, so `check` is stable across machines.

## CI

Install spechurl in the job (or cache the release binary), then fail the build on drift:

```yaml
- name: Contract suite matches OpenAPI
  run: spechurl check openapi.yaml --dir tests/hurl
```

A typical update is:

```bash
spechurl generate openapi.yaml --out tests/hurl
git add tests/hurl openapi.yaml
```

This repository's own workflow (`.github/workflows/ci.yml`) runs `cargo fmt`, `cargo clippy -D warnings`, `cargo test`, and a release build on push and pull request to `main`.

## Fixtures

| File | What it covers |
| --- | --- |
| `fixtures/petstore.yaml` | List, create, read, update, and delete. Query examples, a JSON body, a path parameter, `readOnly`. |
| `fixtures/edge-cases.yaml` | Path parameters with spaces, a required header, a required query enum, a cookie that is noted and skipped, `$ref` examples and responses, `201` preferred over `202`. |
| `fixtures/widgets.openapi.json` | OpenAPI 3.1: `const`, `examples`, `type: [string, "null"]`, and a `2XX` wildcard. |

## Limitations in v0.1

- OpenAPI 3.0 and 3.1 only. Swagger 2.0 is rejected with an error.
- `$ref` must be a local `#/...` pointer. External files and URLs are rejected.
- Cookie parameters, security schemes, callbacks, links, and webhooks are not turned into requests. A cookie parameter is mentioned in a comment so it is not silently dropped.
- One asserted success status per operation, not one entry per documented status.
- Schema samples are minimal. They honor `minimum` / `minLength` and common `format` values (`date-time`, `uuid`, `email`, `uri`, and a few others). They do not satisfy `pattern`.
- `oneOf` / `anyOf` use the first branch. `allOf` merges object samples.
- Array query parameters are sent as a single comma-joined value. `style` and `explode` are not modeled.
- Request bodies that are not JSON, form, text, or XML need an example or they are skipped with a comment.
- spechurl does not run your API. Hurl does that.
